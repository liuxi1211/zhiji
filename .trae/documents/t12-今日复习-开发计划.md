# 4.3 今日复习 · 开发计划（T12 落地）

## Summary

实现 C 端日活锚点「今日复习」（核心模块定义 4.3，原"随机复习"，游戏化命名退役）。交付四块：

1. **今日清单**（默认形态）：`ReviewService` 按四路信号混合推送一小组题（上限 5 题，3 分钟量级）——到期复测（对抗遗忘主引擎）、弱点加权（weak 态题）、抽查验伪（quick 态题低频弹出）、技能条新题（锚定未学的高频必问题）。
2. **随机抽取**（碎片时间）：不设上限连续抽题，来源 = 复习池（quick/pass/weak 知识点）∪ 技能条锚定未学高频必问题；支持按域过滤（考前突击）；两个动态规则第一版就要有——连续答对下调抽中概率、连续答错掺低难度已学题。
3. **复习排期与证据**：`learn_state` 扩展复习参数列（due_at / review_interval_days / fail_count / last_reviewed_at，6.5「学习状态 = 掌握状态与复习参数，学习与复习共用数据源」）；新增 `review_log` 结果流水表（间隔重复状态推导 + 虚报证据累积，T13 复盘降级建议消费）。复测结果只更新复习参数，**不回写 learn_state 五态**（4.3"今日复习不回写学习路径"）。
4. **前端重写 `GachaView.vue`**：今日清单 + 随机抽取双形态页；导航 tab「抽卡」更名「今日复习」；高难度题"进入判定模式"复用既有 `/practice/:kpId` 流程。

**零新增 AI 用途**：抽题与排期全是代码算法；判定模式复用判定引擎既有 purpose（6.4 清单无需登记）。

验收 = `mvn test` 全绿 + `mvn clean compile` + `cd frontend && npm run build` + 冒烟清单全过。

## 领域决策（已拍板，实现不再选择）

| # | 决策 | 依据 |
|---|---|---|
| R1 | **复习参数进 `learn_state`**（加列，不建新表）：6.5「知识点学习状态 = 个人掌握状态与复习参数，学习与复习共用的数据源」——复习排期就是学习状态的一部分 | 6.5 命名表真相源 |
| R2 | **复测结果不回写五态**：known/unknown 只更新 due_at / interval / fail_count / last_reviewed_at + 落 `review_log`；learn_state.status 不动（quick 不因复测不会变 weak、pass 不因复测会升格） | 4.3 边界"今日复习不回写学习路径——复测与验伪只更新自己的复习状态"；弱点加权读 weak 态（学习时产生），复测失败走 fail_count 证据链 |
| R3 | **间隔重复用轻量固定阶梯**（代码写死）：复测通过 → 连对 streak n（从 review_log 推导）映射间隔 `[1,2,4,8,15,30][min(n,5)]` 天，due_at = now + interval；复测不会 → interval 归零、due_at = now（打回复测队列）；progressed 且 due_at 为 NULL 视为到期（首次复测建立排期，兼容 T11 存量行） | 4.3"间隔重复到期复测"；SM-2 全参版属过度设计，阶梯够用且可测 |
| R4 | **虚报/失败证据 = fail_count（累计）+ review_log（流水）**：progressed 行自评"不会"一律 fail_count+1；quick 态的"不会"即虚报（抽查验伪挤水），证据链 T13 复盘降级建议消费 | 4.3"虚报打回复测队列并累积证据"、"授权知识点的虚报/失败累积汇入复盘的降级建议" |
| R5 | **今日清单合成规则**（上限 5，去重）：① 到期复测（due_at NULL 或 ≤ now，按 due_at 升序）≤3 题 tag=due；② weak 态 1 题 tag=weak；③ quick 态抽验 1 题 tag=spot（1/3 概率触发，`Random` 注入可测）；④ 技能条锚定未学（无 progressed 行、非 abandoned、available）按「基线必问优先 → 三路频率降序 → 难度升序」补足剩余槽位 tag=new（≤2）。已复测过的题因 due_at 后移自然出列，当日不重复 | 4.3 四路信号 + "3 分钟量级"；确定性槽位 + 单点随机（抽查触发）保证可测 |
| R6 | **随机抽取池** = 复习池（quick/pass/weak）∪ 锚定未学高频必问题；支持 `domainCode` 过滤（按域集中复习/考前突击）与 `exclude` 参数（前端会话内已抽过的 kpId，池抽空时前端清空重抽） | 4.3 抽题来源公式 + 按域集中复习 |
| R7 | **两个动态规则全用代码权重实现**（纯函数可单测）：连对衰减——该 kp 连对 streak × `1/(1+streak)`（只调概率，不碰到期队列）；连错掺低难——最近 3 条 review_log 全为"不会"时，初级/中级已学题权重 ×3；新题基础权重 0.8、到期 ×3、weak ×3、quick 抽验 ×0.5 | 4.3"第一版就要有"的两条动态规则 + 6.1"规则全在代码"精神 |
| R8 | **随机抽取自评即调 result 接口**：复习池内题按 R2/R3 更新排期与证据；锚定未学题（new）只落 review_log、不建排期不改状态（复习不产生学习推进，正式拿下走练习模式，卡片给"去练习"引导） | 4.3"今日复习不产生新任务"；R9（T11）练习入口对任意 kp 开放承接 |

## Proposed Changes

### A. 数据库（`src/main/resources/db/schema.sql`）

**learn_state 建表定义追加 4 列**（新库直接建；存量库走 SchemaPatcher）：

```sql
due_at TEXT,                                      -- 下次复测到期；NULL=未排期（progressed 且 NULL 视为到期）
review_interval_days INTEGER NOT NULL DEFAULT 0,  -- 当前复测间隔（天）
fail_count INTEGER NOT NULL DEFAULT 0,            -- 虚报/失败累积证据（T13 复盘降级建议消费）
last_reviewed_at TEXT                             -- 最近一次复习自评时间
```

**新表**：

```sql
-- T12 今日复习（核心模块定义 4.3）：复习结果流水。间隔重复 streak 与连错检测从本表推导；
-- 虚报/失败证据同时累计在 learn_state.fail_count（快照列）供复盘降级建议（T13）直读。
CREATE TABLE IF NOT EXISTS review_log (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    profile_id  INTEGER NOT NULL REFERENCES prf_profile (id),
    kp_id       INTEGER NOT NULL REFERENCES kb_kp (id),
    known       INTEGER NOT NULL,                 -- 1=自评会 0=自评不会
    mode        TEXT NOT NULL DEFAULT 'today' CHECK (mode IN ('today','draw')),
    created_at  TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX IF NOT EXISTS idx_review_log_profile ON review_log (profile_id, kp_id, created_at);
```

**ReviewService 职责**：

1. `today(customerId)` → `ReviewTodayView`：
   - 档案守卫（R11）→ 采集：到期行（`LearnStateService.dueRows(profileId)`，quick/pass/weak 且 due_at NULL 或 ≤ now）、weak 行、quick 行、锚定未学题（复制 PathService 的 claimAnchorIds/baselineIds/freqTotal 查询，过滤 progressed+abandoned）；
   - 按 R5 槽位合成 items（去重；spot 触发走 `shouldIncludeSpot(spotCoin())` 纯函数，`spotCoin()` 返回注入的 `Random.nextDouble()`）；
   - 附 stats `{due, weak, quick, new}`（池量统计，空态文案用）。
2. `draw(customerId, domainCode, excludeIds)` → `DrawResp`：
   - 池 = 复习池 ∪ 锚定未学（R6），domainCode 过滤、exclude 剔除；空池 → `REVIEW_POOL_EMPTY`；
   - 权重：`static double weightOf(KpWeightCtx ctx)` 纯函数——base 1.0；due ×3；weak ×3；quick 抽验位 ×0.5；new ×0.8；连对衰减 `×1/(1+min(streak,3))`；`recentWrongStreak(最近3条log)` 为真时 junior/mid 已学题 ×3（R7）；
   - 加权随机取 1 题（`Random` 注入），返回单题卡片视图。
3. `result(customerId, kpId, known, mode)` → `ReviewResultView`：
   - 落 `review_log`（事务）；
   - 该 kp 为 progressed 行：`LearnStateService.recordReviewResult(profileId, kpId, known)` 更新排期（R3 阶梯 + fail_count，R4）；
   - 未学 kp：只落 log，返回 state=learning、dueAt=null（R8）。
4. **LearnStateService（改）追加**：①`dueRows(profileId)`（progressed 且到期，内存过滤）；②`progressedRows(profileId)`（复习池）；③`recordReviewResult(profileId, kpId, known)`——排期唯一写入口：known → streak（ReviewService 从 log 传入）映射阶梯 interval、due_at=now+interval；!known → interval=0、due_at=now、fail_count+1；last_reviewed_at=now；status 不动（R2）。

### E. 测试（新建 `src/test/java/com/zhiji/review/ReviewFlowTest.java`）

骨架照抄 LearnFlowTest。种子：kp A（mid required=1）、kp B（无信号）、kp C/D（claim 锚定）；客户注册 → 建档 → 定稿 → 锚定 A/C。用例：

1. **未定稿拦截**：draft 态 `GET /api/review/today` → 400；finalize 后 200；
2. **到期复测**：A quick 后（due_at NULL）→ today 含 A tag=due；result known=true → due_at=明天起、interval=1、review_log +1；再构造到期（直接改 due_at 为过去）→ 重新出现 tag=due；
3. **阶梯递增**：连续 3 次 known（间隔日志）→ interval 依次 1→2→4；
4. **弱点加权**：B 置 weak（quickEval unknown）→ today 含 B tag=weak；
5. **抽查验伪**：A 置 quick + Random stub 返回 0.0（触发 spot）→ today 含 A tag=spot；result known=false → fail_count=1、due_at=now（打回）、state 仍 quick（不回写五态，R2）；
6. **技能条新题**：C 锚定未学 → today 含 C tag=new；result known=true → learn_state 无 progressed 行（不建排期）、log 落库；
7. **空清单**：无到期/weak/spot 触发/锚定 → items 空 + stats 全 0；
8. **随机抽取池**：A quick 后 draw 命中池内题；全部排除（exclude=A）→ 400 `REVIEW_POOL_EMPTY`；
9. **动态权重（纯函数单测，不改 Spring 上下文）**：`weightOf`——due ×3、weak ×3、new ×0.8、连对衰减 `1/(1+streak)`、连错低难 ×3；`shouldIncludeSpot(0.0)=true / (0.9)=false`；
10. **result 越权与校验**：未登录 401；known 缺失 400；mode 非法 400；
11. **域过滤**：draw 按 domainCode 只返回该域 kp；
12. **不回写验证**：一系列 result 后 A 的 learn_state.status 保持 quick 不变（R2 核心断言）。
