# 4.2 学习路径与练习 · 开发计划（T11 落地）

## Summary

实现 C 端日常学习主入口「学习路径与练习」（核心模块定义 4.2）。交付四块：

1. **学习路径**（前端重写 `MapView.vue`）：后端 `PathService` 每次实时推导阶段/单元（**不落表**），四路信号并集准入——技能条锚定知识点（主攻）、目标职级基线必问集（打底）、JD 命中（定制）、复盘信号（一期空集，枚举预留）；并集之外不进路径、不留痕。
2. **学习单元**（新增 `UnitView.vue`）：单元内知识点列表（状态点 / 难度 / 信号 / 锁定 / 豁免卡）+ 单元验收刻度尺。
3. **双节奏练习**（新增 `PracticeView.vue`）：**练习模式**闭卷作答、复用判定引擎逐层下钻，判定通过才算完成（`learn_state.status=pass`）；**速览模式**先自测后看三档样例、自评直接推进（`quick`/`weak`，进抽查范围）。
4. **学习状态与护栏**：新增 `learn_state` 表（五态状态机）；放弃/恢复、前置锁定、档案未定稿引导、并集为空空态、判定降级兜底。

前端**严格按原型** [learning-path-practice.html](file:///d:/ideaProject/zhiji/frontend/prototypes/learning-path-practice.html) 的视觉语言实现：**验收刻度尺**（实心/空心铜/斜纹/空白/灰虚五态）、双节奏卡片、移动优先 + PC 两栏。

验收 = `mvn test` 全绿 + `mvn clean compile` + `cd frontend && npm run build` + 冒烟清单全过。

## Proposed Changes

### A. 数据库

**`src/main/resources/db/schema.sql` 追加**：

```sql
-- T11 学习路径与练习模块（核心模块定义 4.2）：知识点学习状态（6.5，学习与复习共用数据源）。
-- 学习路径不落表（阶段/单元每次实时推导，R1），个人进度全挂本表。
-- 状态机：learning → quick|pass|weak；weak → quick|pass；abandoned → learning（恢复）；任意 → abandoned。
-- quick=速览自评会（抽查范围）；pass=练习判定通过；weak=速览自评不会（弱点加权）；
-- 三态均算已推进（单元完成度与复习池入池口径），progressed_at 为 T12 间隔重复时间起点。
CREATE TABLE IF NOT EXISTS learn_state (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,
    profile_id     INTEGER NOT NULL REFERENCES prf_profile (id),
    kp_id          INTEGER NOT NULL REFERENCES kb_kp (id),
    status         TEXT NOT NULL DEFAULT 'learning'
                   CHECK (status IN ('learning','quick','pass','weak','abandoned')),
    session_id     INTEGER REFERENCES judge_session (id),  -- 最近一次练习判定会话
    abandon_reason TEXT,                                   -- 放弃原因（可选填）
    progressed_at  TEXT,                                   -- 达成 quick/pass/weak 的时间
    created_at     TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at     TEXT NOT NULL DEFAULT (datetime('now')),
    UNIQUE (profile_id, kp_id)
);

CREATE INDEX IF NOT EXISTS idx_learn_state_profile ON learn_state (profile_id, status);
```

**`judge_session` 建表定义同步加列**（供新库；旧库走启动补丁）：

```sql
owner_type TEXT NOT NULL DEFAULT 'staff'
-- staff=试判台（B 端员工）  customer=练习模式（C 端客户，此时 created_by 存档案 id）
```

**新建 `src/main/java/com/zhiji/config/SchemaPatcher.java`**（`ApplicationRunner` + `@Order(Ordered.HIGHEST_PRECEDENCE)`，早于业务校验）：`PRAGMA table_info(judge_session)` 无 `owner_type` 则 `ALTER TABLE judge_session ADD COLUMN owner_type TEXT NOT NULL DEFAULT 'staff'`，幂等；照抄 [ProfileSchemaPatch.java](file:///d:/ideaProject/zhiji/src/main/java/com/zhiji/profile/config/ProfileSchemaPatch.java) 写法。

## Assumptions & Decisions

| # | 决策 | 理由 |
|---|---|---|
| D-1 | **客户会话 `created_by` 存档案 id**（`owner_type=customer` 时）；不新增 `profile_id` 列 | `created_by` 现为 NOT NULL，客户无员工 id 可填；`owner_type` 已区分命名空间，避免为一条信息再加列（对齐 t11 R7"不动表结构"精神） |
| D-2 | `JudgeService` 各判定方法**加 `long profileId` 形参**（而非会话行冗余 profile_id 列）透传 `LlmRequest` | 对齐 t11 R7 选择；调用点少（JudgeController + PracticeService） |
| D-3 | 练习页**不复用 `KpDisplay.vue`**（R13） | KpDisplay 一次展示全部答案，与闭卷作答冲突 |
| D-4 | 路由为 `/unit/:topicId`、`/practice/:kpId`（非 t11 文中 `/learn/...`） | 与现有 learn 子路由扁平结构一致，且不动 `LearnLayout.tabs` 导航数据源 |
| D-5 | 错误码新分段 `LEARN_*`：`LEARN_PROFILE_NOT_FINALIZED`(400)、`LEARN_KP_NOT_AVAILABLE`(400)、`LEARN_SESSION_OWNED`(404) | 对齐 `PRF_*`/`KB_*` 分段惯例 |
| D-6 | `PathService` 实时计算不加缓存 | 50–500 kp 量级单次 <50ms，缓存引入失效复杂度不划算 |
| D-7 | weak 算推进；练习进度不改 T12 复习调度 | 4.2"练习纯推进，复习交给今日复习"；两个模块节奏互不污染 |
