# 知己 · 核心模块定义

> 这份文档是开发任务拆分的原子单位清单：每个模块一段，讲清概述、含义与边界。C 端与 B 端只是前端的页面组织（同一份构建产物，靠路由 `/` 与 `/admin` 区分），后端始终是一个单体工程，下列模块都是这个单体里平行的业务模块。上游产物是 [00-项目企划书](项目企划书.md)（产品流程与判定规则）、[考点库PRD](考点库PRD.md)（内容资产与生产管道）、[系统架构设计](系统架构设计.md)（后端包边界与表归属）。

## 一、模块总览

| # | 模块 | 后端包 | 前端入口 | 一句话职责 |

| 2 | 生成副本 | learning | /dungeons（C） | 按简历把考点库裁成多塔副本：新手村塔 + 域塔，楼层难度递进，通关即学完 |

## 二、C 端模块

### 2.1 建档

用户进入产品的第一站，也是简历档案的管理入口。每个用户最多维护 3 份简历档案，档案是备考上下文的顶层归属：一份档案包含简历原件与解析文本、技能画像、备考计划、项目素材，生成副本、爬塔、抽卡、模拟考、复盘的个人态全部挂在档案下，切换档案即切换备考上下文，进度互不污染。建档动作发生在档案内：有简历就上传解析，没有简历就跟 AI 聊——年限、岗位、做什么、用过什么。AI 从简历和对话里整理出技能画像草案，用户逐条拍板：不熟的删掉、漏掉的加上、措辞不准的改掉。对话里聊到的项目细节（数字、冲突、结果）作为项目素材沉淀下来，后续成为项目叙事和模拟考追问的原料。

含义与边界：

- 产出四样东西：定稿的技能画像（user_skill）、目标职级、备考计划（目标岗位/JD/周期/每日时间，user_plan）、项目素材（user_case），全部归属当前简历档案。目标职级（初级/中级/高级/资深/专家）是全链路的深度标尺：过关停止点、新手村塔组成、模拟考下钻深度都由它推导；建档时用户明确说了就采用，没说就按工作年限推测缺省值，用户随时可改——32 岁面中级岗，全套按中级复习，完全合法。
- 画像走状态机（草稿 → 确认 → 定稿），未定稿的画像不参与生成副本。
- LLM 在这里只做整理与起草，事实由用户逐条确认；建档不答题、不摸底，入口永远没有考试。
- 简历主张的降级/升级建议写回触发它的那份档案，档案间互不串写。
- 不碰考点内容，不碰练习进度。

落点：后端 profile 包，拥有简历档案实体；依赖技能库（画像候选项）、文档解析（简历抽文本）与模型接入（整理草案）。

### 2.2 生成副本

基于档案内定稿画像与备考计划，把考点库裁成属于这份简历的一座座可打副本。检索与组织分开：检索用技能条、项目素材、目标 JD 和**目标职级**去匹配考点，决定哪些内容进副本、权重多高；组织不按技能条（个人态，增删改名会抖动骨架），按考点库现成的「技能域 → 主题簇 → 考点」结构展开为**多塔制**——每个域一座塔，塔内按主题簇分楼层、楼层内按难度与前置拓扑排序；职级基线做成第一座「新手村塔」（不分域的目标职级必问基础，靠前快速过）。先爬哪座塔用户自选（系统给默认序：新手村 → JD 相关 → 库级频率信号 → 授权密度），全部塔通关 = 这份简历的考点库学完。跨域前置在副本地图上表现为锁：前置所在塔未通到相应楼层，本塔楼层上锁，防止跳跃式推进。

来源与权重不落库，全部消费时推导（企划书原意："聚合权重按两个字段推导，不单独存库"）：某考点是否简历授权，由它是否匹配当前档案定稿画像的技能条推出，承载模拟考聚合权重 ×1.5 与简历主张存活率的定义域；是否职级必问（进新手村塔），由目标职级的基线规则推出，承载权重 ×0.8；是否信号回流，由 user_kp_signal 反查得出。副本数据只存塔与楼层的序列本身（顺序、前置锁、放弃决策），不存任何来源标记。

不进副本的内容分两种。一种是未命中：画像授权、职级基线、JD 与个人信号都不指向的内容，天然不进，不展示也不留痕。另一种是显式放弃：用户在副本地图或爬塔途中对楼层里的题手动点击放弃，它移出塔、进入放弃分区，原因可选填。放弃清单 v1 只由用户手动维护，系统不做自动标定（职级×时间预算的自动减法、算法手撕的预置放弃都不做，留到以后）；算法手撕在考点库范围外，副本地图上以一行静态说明提示替代方案（LeetCode），不做成数据。重新生成副本保留用户的放弃决策，不重新计算。

含义与边界：

- 域与难度之争的取舍：多塔制让"域放在一起"（塔内）与"难度递进"（楼层内）同时成立，牺牲的只是跨域全局难度递进——跨域难度本不可比，这个牺牲是干净的；跨域依赖用锁表达。
- 难度不是准入门槛，只是排序属性：进塔的题集由四信号（画像授权、职级基线、JD、复盘信号）并集决定，任一命中即进，与难度无关；难度只决定楼层内的排序与卡面颜色。禁止任何"按用户职级过滤难度带"的逻辑（如高级只抽橙红卡）——那会结构性漏题：同一道题对不同目标职级的用户是同一道，差的只是过关深度（见 2.3 停止点）。
- 画像条目删除的语义是修正真实水平，不是决定不学：职级基线与 JD 信号不随删除消失（HashMap 对面中级岗的人必问，删了反而更需要练）；"不学"只发生在放弃分区的显式决策里。
- 核心动作是"裁"：每个考点的具体内容不现场编，从预制考点库按需取用，点开才渲染；副本地图是独立页面，C 端日常主入口。
- 可重开：复盘信号回流、简历主张降级之后重新生成副本；重生成只重写塔与楼层（user_path），练习进度（user_kp_state）原地不动，爬塔游标按新序列与掌握状态重新定位。

落点：后端 learning 包（与过副本、抽卡同包，开发任务独立），产出挂在简历档案下；依赖考点库（读考点、难度、前置、域与簇）、建档（读定稿画像）、复盘（消费个人信号，走数据回流，见第五节）。

### 2.3 过副本

日常主体。副本地图上选一座塔进入爬塔页，任务是过这个副本：从当前楼层继续往上，塔顶即该域通关、解锁 Boss 战。爬塔不设"每日抽卡"，去哪座塔、爬几层完全由用户自控，没有随机调度。

每个楼层就是一张闪卡关卡：初始只展示题目，用户先回忆，再翻面看标准答案；有更深一层的关联题目（追问）就展示入口；看不懂展开知识簇看从零详解；还不懂，后续版本针对这道题与 AI 对话交流。过关方式两种节奏并存、用户自选：闪卡快过——翻面自评「过了」直接上楼（想快速过一轮拿印象的人）；练习模式扎实过——闭卷口述/打字作答，先作答才解锁自评，作答经判定引擎驱动下一步（继续下钻、同层换角度再问、回退前置考点），答过才算通关。卡面上「我不会」与「我会，跳过」合并为过关选择：标了"不会"的卡进抽卡的弱点加权与复测队列；不想要的题可点击放弃，移出塔进放弃清单。

含义与边界：

- 爬塔纯推进、塔内不回头：复测与复习全部交给抽卡模块，爬塔只负责向前——两个功能互不打扰，节奏各自干净。
- 练习模式不设场次实体：逐层作答逐层判定，attempt 仅模拟考使用（练习作答的判定历史 attempt_id 为空）。
- 同一道题，不同目标职级过关深度不同：过关标准由考点的职级要求（下钻停止点）决定——面中级答到第 1 层算过关，面资深要扛到第 3 层；停止点之下的更深追问层照样可见（学无止境），但目标刻度明确标注"到你目标职级讲到第 N 层算够"。同一座塔对不同用户是不同题集（四信号裁剪）+ 相同题目、不同尺子（停止点）。
- 漏题的三道防线：并集准入（不做难度/职级过滤）；复盘兜底（真被问到的题不在塔里，录题回流下次生成进塔）；标定进校对清单（职级基线与停止点的完整性是内容管道人工校对的必检项，见 3.3）。
- 楼层即关卡，重玩成本低：单层 3 分钟量级，随时进来随时爬，进度就是"爬到第几层"，不需要每日任务感。
- 过关选择里"不会"是抽卡的输入信号（弱点加权 + 复测队列），"我会，跳过"进抽查池由抽卡验伪——自报水分的挤压器在抽卡侧。
- 卡面按考点难度配稀有度颜色：难度约定为 1~5 整数档，与白/绿/黄/橙/红五色一一对应（1 最易、5 最难）。爬塔、副本地图、抽卡积分共用同一套难度配色；颜色只编码难度，简历授权等来源信息用角标区分，不抢颜色语义。
- 题卡内容映射，爬塔、抽卡、模拟考三处共用同一套卡结构：正面 = 题面（练习与模拟考中按问法变体或现场改问法呈现）；背面 = 标准回答样例，默认展开及格档，良好/优秀两档可展开；追问入口 = 追问链，按 layer_key 逐层展开；看不懂 = 展开主簇的从零讲；目标刻度 = 该考点职级要求按当前目标职级渲染出的停止点（「讲到第 N 层算够」）。评分要点只进判定引擎，不上卡面。
- 楼层与过关口径：楼层 = 主题簇，楼层过关 = 楼层内全部考点过关，到塔顶即全塔通关；过关选择（过了 / 不会 / 我会，跳过 / 放弃）与练习模式判定结果统一写 user_kp_state——它是爬塔游标、抽卡卡池与三条抽卡信号的共同数据源，抽卡卡池即 user_kp_state 中已过关考点的集合。
- 项目叙事的练习（看标准故事 → 练习模式讲 3 分钟）归这里；标准故事由档案内建档素材起草，六要素组织，每个数字和事实逐条经用户确认。叙事卡的库侧承载是 sub_type=narrative 的模板考点（题面模板 + 指标清单评分要点，不含任何个人内容），个人标准故事挂 user_narrative 并关联模板考点与档案，多项目按 project_name 区分——库/态分离在叙事题型上的落地。

落点：后端 learning 包，状态挂在简历档案下；依赖判定引擎（仅练习模式与模拟考消费）、考点库、生成副本（塔序列与练习态分表，重新生成不动练习进度）。

### 2.4 抽卡

随机学习与随机检验的轻量入口，全部复习机制在这里。用户随时抽一把：全随机或指定域，每次几张，适合碎片时间。卡池 = 已爬过楼层里的卡（爬塔走过的部分），按三条信号混抽：SM-2 到期的复测卡（间隔重复的主引擎）、抽查池到期的验伪卡（爬塔时标「我会，跳过」的卡，低频弹出翻面复验，虚报打回复测队列并累积虚报证据）、爬塔时标「我不会」的弱点卡（掉率上调）。抽卡既是复习器也是自报水分的挤压器，爬塔因此可以放心纯推进。

抽卡体验轻：翻面自评为主，橙红高难卡可选进入判定（想要真检验时用）；小积分与连击这类轻趣味按需加，不设正式报告。

混抽权重按会话状态动态调整，第一版就要有：连对降权与送分题。连续答对的卡在随机混抽中下调抽中概率（只调概率，不碰 SM-2 到期队列与抽查池的入场资格，权重设下限不为零——"变没"交给间隔重复去做）；连续答错达到阈值时，后续抽卡掺入少量已过关的低难度送分卡（难度 ≤ 2，对应白绿卡面），重建连击与掌控感。两者互补关系：SM-2 管"错的卡间隔重置后回来"，送分题管"连错时当场给正反馈"；送分卡作答结果照常写 SM-2 参数，就是一次正常复习，不产生额外状态。连对/连错计数落 user_kp_state 标记位，不加表。

含义与边界：

- 三条抽卡信号（到期复测、抽查验伪、弱点加权）都由爬塔的过关选择喂养，抽卡不自己产生新任务：闪卡自评、练习判定、抽查复验都更新 user_kp_state 的 SM-2 复习参数与标记位（弱点标记、抽查池状态、虚报证据计数），字段随详设定稿。
- 指定域抽卡天然支持考前抱佛脚：明天面 ES，今晚连抽 ES 塔。
- 抽卡数据（复测通过、虚报证据）回流影响两个下游：弱点卡决定掉率，简历授权卡的虚报/失败累积汇入复盘的降级建议。

落点：后端 learning 包，与过副本共享练习态；依赖考点库、生成副本（界定可抽卡池）。

### 2.5 模拟考

复习好了来一套的全真检验：有时间限制、有评分、出题规则贴近真实面试。分两级入场——分域 Boss 战：每座塔通关解锁该域的限时域考，规模小、即时检验；终局模拟考：全部塔通关解锁，全量限时考试，方向轮转组卷（先横切再纵深），每答一问判一次、判定驱动追问（对则下钻、缺则继续钻、错则温和纠正后同层换角度、空则切题），考完出三样东西：加权及格率（映射四档总评：优秀/良好/及格/不及格）、简历主张存活率、教练总评（LLM 只写叙述与归因，不给分）。

含义与边界：

- 简历主张存活率 = 本场抽到的简历授权考点里没被打穿的比例（授权由画像匹配推导）；连续两场低于 50% 自动触发简历降级建议——"简历和考点库互相改"的量化落点。
- 中途喊停的场次照常出报告，标"未完成不评级"；连着两场喊停，考前说明里给提醒。
- 设计演进链以演进链形态进模拟考，平行方向乱序抽层防背题；未覆盖方向进下次优先队列，覆盖度进报告。
- 跨场趋势（断在第几层、扛了几层、深度分布演变）比单场评级值钱。

落点：后端 exam 包；依赖判定引擎、考点库、learning（只读爬塔进度，界定 Boss 战与终局考试的解锁条件）。

### 2.6 复盘

真去面了，回来把被问到的题录进去。能对上已有考点的，写成个人复盘信号（权重最高的频率信号），直接驱动副本重排；对不上的，进考点库候选池，成为考点库的生长点。同时触发它的那份档案里，路径和简历跟着更新：练不住的主张从简历降级，练深了的考点反过来写成简历亮点。

含义与边界：

- 体量小、杠杆大：五环节里唯一由真实面试驱动的环节，也是"考点库不是建完的，是长出来的"这句话的入口。
- 个人复盘信号与库级频率信号分开存放：前者是隐私资产、随面试次数累积；后者是公共信号，只含面经信号与人工标定。
- 录题匹配考点的前提是 C 端能搜到考点：需要按题面模糊检索 active 考点的搜索接口（接口清单见第六节待同步项）；匹配由用户确认，不做 AI 静默归并——归并错了会污染权重最高的个人信号。
- 与模拟考同属 exam 包，但作为独立开发任务，因为它横跨"录题回流"与"简历升降级"两条链路。

落点：后端 exam 包，拥有 user_kp_signal 表；依赖考点库（考点匹配与候选池）、生成副本（重排触发）。

## 三、B 端模块

### 3.1 技能库

全局一份的技能域字典。它有三重身份：建档时技能画像逐条拍板的候选项（用户从中认领或补充，形成个人画像）；考点库里考点分域的归属依据；简历主张与考点之间的授权锚点——画像条目经由技能域关联到考点，主攻层"简历上写了的"由此成立，简历主张存活率也以它为锚。

含义与边界：

- 字典是内容资产，不随用户变化；B 端维护，C 端只读。
- 归属判断：它是三处消费的字典，塞进任何业务模块都会造成反向依赖，因此独立成模块。
- 简历的项目部分不在这里承载——项目素材在建档采集，六要素模板在考点库，见 2.1 与 3.2。

落点：后端 skill 包，拥有 skill_domain 表；被建档、考点库、生成副本依赖。

### 3.2 考点库

产品的核心资产，全局一份，存的是结构化的"面试怎么问、怎么判"：考点（题面、问法变体、叙述框架、追问链带层身份与方向、分级评分要点、职级要求与下钻停止点、难度、前置考点、主主题簇）、主题簇（从零讲与完整参考方案的生产共享单位）、前置依赖（学习维度，可跨簇，多数 0~2 个不硬凑）、库级频率信号（面经信号与人工标定）。

含义与边界：

- 命名口径：本模块与全库统一叫**考点库**——原子单元是考点，主题簇、前置依赖、追问层、评分要点全部围绕考点组织；"题库"这个词只留给竞品语境（刷题网站的题库、市面上的题库工具），面向用户的题面、题卡、考题等"题"字表述不受影响。
- 题型收敛为一类知识点，差异下沉到 sub_type：默认八股 / 设计演进链 / 项目叙事；全局骨架（如项目叙事的六要素模板）也放这里，全局一份。
- 每条内容必须过状态机（draft → reviewed → active），不校不上线；上线后有复核到期机制，过期内容回人工复核队列。
- 库/态分离是根基：考点库只回答"有哪些考点、结构是什么"，不感知任何用户。
- 概念边界最值钱也最容易守错：追问层是考点的内嵌结构（layer_key 永不复用），主题簇是生产单位，前置依赖是学习维度，难度与职级要求互不推导，三者两两正交。
- 字段约定：难度为 1~5 整数档（对应卡面五色）；每个追问层必须标所属方向 dir，主问题层方向固定为 main，方向是模拟考横向轮转与覆盖统计的分组键；追问链编辑只许改文本与顺序，层的增减走「新增层 / 停用层」，停用层的 layer_key 不得再分配给新层——这是红线 2 的操作化。
- 簇先于考点存在（kp_main 挂且只挂一个主簇，外键决定建簇在前）：建簇入口两处——管道聚类环节按素材聚簇加人工确认、B 端考点库页手工建簇/改簇/合并簇；簇级内容（从零讲、完整参考方案）与考点走同一套状态机。

落点：后端 kb 包，拥有 kp_cluster / kp_main / kp_prereq / kp_freq_signal 表；B 端 /admin/kp 同时管簇与考点（建簇、合并簇、校对流转、复核队列）；被生成副本、过副本、抽卡、模拟考、判定引擎依赖。

### 3.3 内容管道

考点库的供应链。七环节：采集素材（面经、开源仓库只取"哪些题高频、问到什么深度"的信号，不抄正文）→ 文档解析与拆题（先人工核对解析预览，再按标题/题号/LLM 三档策略拆进候选池）→ 聚类去重（语义映射到已有考点，同一考点的多种问法归一为变体；映射不上的新考点在此完成分簇——归入已有簇或新建簇，簇是考点入库的前置）→ AI 成稿（固定模板生成，过结构校验防键名漂移）→ 人工校对（技术正确性、评分要点可判定性、变体覆盖面、从零讲的比喻）→ 入库上线（状态流转，频次信号同步入库）→ 持续演化（复盘信号回流为新增内容的来源，判定数据反过来暴露评分要点的质量问题）。

含义与边界：

- 版权红线：解析出的素材文本只是 AI 重写的输入，成品必须经重写加人工校对，原文以来源链接标注；解析文本只留在素材文档里，不进考点内容。
- 去重是生命线：管道里语义匹配加人工确认，入库时唯一约束再兜一道；同一考点重复入库会稀释练习时间、分裂判定数据。
- v1 可以极简实现（手工录题 + AI 辅助成稿），但模块边界与"不校不上线"的安全线从第一天就有——考点库不会自己长出来，这条管道决定内容质量的上限。

落点：后端 pipeline 包，拥有 kp_candidate / kp_source_doc 表；依赖考点库、模型接入、文档解析。

## 四、无界面的共享模块

### 4.1 判定引擎

产品可信度的根。LLM 只做对齐判断、不做知识判断：评分要点是考点库里预制的尺子，判定引擎的唯一职责是把用户的自由回答对齐到尺子上，输出强制 JSON，判定规则全部写在代码里。

含义与边界：

- 三条硬规则：答况四分流（对/缺/错/空，判定驱动追问）；引用强制（命中要点必须附用户原话，引不出算未命中）；档位公式（优秀/良好/及格/不及格由命中分布确定性算出，LLM 从不碰分数）。
- 每次判定留要点快照（layer_key + level + 文本）：内容校对只影响未来判定，历史判定始终可解释、可比，跨场曲线才可信。
- 降级路径：LLM 失败重试一次，再失败解锁自评按钮——判定永远不是单点故障。
- 被模拟考与爬塔的练习模式消费（闪卡快过与抽卡翻面自评不触发判定）；消费方少但规则是全局尺子，归属任何一方都会让规则随业务漂移，因此单列。

落点：后端 judge 包，拥有 answer_log 表（写入方，learning/exam 读取）；依赖模型接入与考点库（读评分要点）。

### 4.2 支撑能力

三个无业务语义的技术模块。模型接入（llm）屏蔽 provider 差异：按用途路由模型（判定用便宜模型温度 0、总评用好模型）、装载 prompt 模板、校验返回 JSON、失败重试与降级，换模型服务商只改配置不改业务代码。文档解析（docparse）把 pdf/doc/docx/md/txt 变成干净纯文本，建档的简历解析与内容管道的素材解析共用同一能力；扫描件明确报错不静默。到期调度（scheduler）定时触发复测计算与内容复核，调度状态持久化在库里，重启不丢。

含义与边界：这三个模块不解释业务语义、不持有业务规则；换模型、换解析库、换调度方式，改动收敛在各自模块内。

落点：后端 llm / docparse / scheduler 包；被多个业务模块依赖，不反向依赖任何业务。

## 五、依赖方向与红线

依赖关系沿用系统架构设计的包依赖，含技能库独立后的调整：

- 建档 → 技能库；生成副本 → 考点库、建档；过副本 → 判定引擎、考点库、生成副本；抽卡 → 考点库、生成副本（共享练习态，无编译依赖新增）；模拟考 → 判定引擎、考点库、learning（只读）；复盘 → 考点库。
- 判定引擎 → 模型接入、考点库；内容管道 → 考点库、模型接入、文档解析；建档 → 文档解析、模型接入。
- 复盘信号回流到副本重排的权重，走数据流而非编译依赖：复盘写 user_kp_signal，生成副本在重排时消费，具体读取方式在详设时定，避免与"模拟考只读 learning 状态"形成环。
- 依赖图无环；跨模块只走对方的 api 包，repo 不出模块；web 层只依赖领域模块。

四条领域红线，任何模块的实现都不得违反：

1. 分是公式算的，LLM 从不碰分数；判定规则在判定引擎实现，不交给模型。
2. layer_key 是追问层的稳定身份，永不复用、永不修改，禁止用数组下标作身份。
3. 库/态分离：全局内容进 kp_*，个人数据进 user_*，用户独一无二的内容绝不进全局库表。
4. 不校不上线：未过人工校对的考点库内容不许进用户路径；库校对只重写内容，不碰用户进度。

## 七、待办备忘（暂不做，防止遗忘）

- **职级基线与停止点标定**：这是漏题风险的真实所在（不在难度映射——那已结构性排除）。标定键统一为「考点 × 职级档位」（初级/中级/高级/资深/专家），年限只是建档时推测缺省职级的参考，不是标定维度；需标定两样：哪些考点对哪个职级档位必问（决定新手村塔组成，面中级岗就有中级的新手村）、每题每档停在第几层（决定过关尺子）。标定粒度详设时定；人工校对清单加入完整性检查项。承载已拍板：kp_main 的 level_req JSON（每档 required + stop_layer）加 baseline_levels 查询实列，不新增表，结构见考点库设计 5.3；剩余待办是标定内容本身。

- **成就系统**：每个技能域一个成就（如 Redis 域、Elasticsearch 域），用户打通该域副本的全部题目即获得；成就形态为头像或标签，展示在个人资料上，所有人可见。多域成就叠加可表达"多个领域精通 = 大神"这类身份信号。前置依赖：公开展示意味着个人数据要脱离"单机自用"的边界（现架构无认证、无多用户资料页），等认证与多用户体系立项时一起做。触发条件上注意：成就判定应基于塔的通关状态推导，不新增独立打卡表。
