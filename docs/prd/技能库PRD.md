# 知己 · 技能库 PRD

> 上游产物是[核心模块定义](../核心模块定义.md) 2.1（建档）与 2.2（生成关卡）。本文档是技能域的真相源（决策清单 D25 目录收口、D30 拍板），说明技能条是什么、怎么生成、怎么锚定知识点、与四信号并集和简历存活率的关系，以及域字典的去留。T3 已缩编为设计任务，本文档即其产出；生成实现并入 T10 建档。

## 一、需求背景

### 1.1 简历的个人能力段落是活的

简历"个人能力"部分不是一张静态清单，而是随人、随岗、随投递版本变化的活文本。同一个 8 年 Java 候选人，投搜索岗和投业务岗的能力段落分组与措辞完全不同（投递版超两页还要把"分布式与系统设计"拆成两条）。目标形态示例（占位符风格，实际生成内容因人而异）：

> - **搜索引擎与检索架构**：【X】年搜索系统研发经验，精通 Elasticsearch / Lucene 内核与工程实践：倒排索引与段结构、BM25 相关性打分、近实时写入链路、分片规划与路由；具备写入与查询性能调优、深分页治理、大查询限流熔断的实战经验（检索规模【N】亿级文档，QPS【X】，P99【X】ms）。
> - **存储与中间件**：熟练使用 MySQL / Redis（索引设计与事务、数据结构与场景选型、穿透 / 击穿 / 雪崩治理）、RocketMQ（消息幂等、顺序、积压治理）；具备自建到云产品的选型、迁移与版本升级实战。
> - **工程与协作素养**：【X】年线上系统稳定性经验，负责线上紧急问题处置与核心方案评审；坚持技术文档化，持续维护个人技术知识库（沉淀【N】+ 篇）。

这样的内容人工预组装不现实：分组的粒度、条数、措辞都要因人制宜。原设计（决策清单 D26）让用户从技能域字典逐条认领画像条目、再挂到主题簇作授权锚点——字典维护有成本，条目表达僵化，且"哪个知识点被授权"要靠生成关卡时的模糊匹配推出，不稳定。

### 1.2 拍板：LLM 生成技能条 + 考点 ID 直接锚定

2026-09-24 拍板（决策清单 D30）：技能条由 LLM 基于档案事实与知识库菜单**两阶段生成**，用户逐条确认；每条技能条**直接锚定知识点 ID 集**，授权判定从"消费时模糊匹配"变为"确定性查表"。技能域字典的三重身份中两重被替代（建档候选 → 技能条生成；授权锚点 → 考点锚定），只剩"知识点分域归属"，B 端域管理页随之取消（B9 收口）。

### 1.3 贯穿原则

LLM 在这里做的是**选择与组织**（把人的经历对齐到预制知识菜单），不是知识判断：知识点内容全部预制（与红线 1"LLM 只做对齐判断"精神同源），技能条只决定"这份简历主张什么、对应练哪些题"。凡是能预判的（菜单、约束、校验）都不交给模型现场编。

## 二、产品目标

| 目标 | 达成标准 |
|---|---|
| 技能条即简历能力段落 | 生成结果可直接作为简历"个人能力"部分的草稿；用户编辑确认后生效 |
| 授权确定性 | 生成关卡时"是否简历授权"由定稿技能条的锚定集查表得出，同一档案重复生成关卡授权口径不变 |
| 生成可控 | 幻觉考点 ID 进不了库（菜单约束 + 后端校验）；结构不合法的生成结果被拒绝 |
| 边界不破坏 | 四信号并集裁题集的现行口径不动；库/态分离不动（技能条全部在 user_* 侧） |

## 三、核心概念

### 3.1 技能条

技能条是简历"个人能力"部分的一个分组段落，同时是授权与学习的锚定单元：**一段简历措辞 + 一组它主张的知识点**。一条技能条通常对应一个能力主题（搜索引擎与检索架构 / 存储与中间件 / 工程与协作素养），条数随人变化（典型 5~10 条）。

技能条取代原设计的"画像条目"（D26 的挂簇主张项）：原条目是短认领项、挂簇作粗粒度锚点；技能条是完整简历段落、直接锚定到知识点。

### 3.2 锚定关系

- 每条技能条锚定 0 ~ N 个知识点（kp_main）；
- **跨条重复合法**：同一知识点被两条技能条同时主张是真实简历的正常形态（Redis 同时出现在"存储与中间件"与"分布式与系统设计"），并集语义，不去重；
- **0 锚定条合法但标记**：软素质条（工程与协作素养、AI 研发效能）可能不锚定任何知识点——正常保留进简历，打 anchor_empty 标记，不进简历主张存活率的定义域（与 D26"挂 0 簇不进存活率"同语义）；
- 簇在生成时只是**检索分组**（阶段 2 按簇出菜单），不再承担锚点职责——簇的授权锚点身份随本 PRD 移除。

### 3.3 与四信号并集的关系（现行口径不动）

生成关卡的题集仍由四信号并集决定（核心模块定义 2.2）：**技能条锚定授权** ∪ 职级基线（基础关组） ∪ JD 匹配 ∪ 复盘回流信号。技能条只接管其中"画像授权"一个信号，把它从模糊匹配变成查表；职级必问的基础关组照旧独立成组——技能条没提到的中级必问题（如 HashMap）不会漏（漏题三道防线不变）。

## 四、生成模型（两阶段）

### 4.1 输入

| 阶段 | 输入 |
|---|---|
| 阶段 1：起草技能条 | 档案事实（建档对话整理：年限、岗位、目标职级、技术栈自述、项目素材摘要）+ 库侧域/簇菜单（域、簇名、簇简介、簇下知识点数） |
| 阶段 2：逐条锚定 | 单条技能条（标题 + 段落）+ 该条覆盖范围对应簇下的知识点菜单（ID、题面、难度、一句话简介） |

一次生成不完的处理：先由阶段 1 按域/簇生成技能条骨架，再对每条技能条分别调用阶段 2 选考点——上下文从"全库"降到"域摘要 + 单簇菜单"，库到几百上千条知识点时依然成立。

### 4.2 产出与结构校验

阶段 1 产出技能条骨架（标题、段落、覆盖的域/簇范围）；阶段 2 产出每条的锚定考点 ID 列表。产物落库前必须过后端结构校验：

- 锚定 ID 必须存在于库且状态为 active（**ID 菜单约束**，幻觉 ID 拒绝并重试）；
- 条内锚定去重；条数上下限（上限随 T10 定，初版 15 条）；
- 0 锚定条打 anchor_empty 标记，不算错误。

### 4.3 事实数字的口径（拍板：不过分干预）

技能条中的数字与经历断言（【X】年、【N】亿文档、QPS【X】）：**LLM 自由生成，有就有、无就无，不设强制确认流**；生成质量靠提示词持续优化收敛。配套两件零成本兜底：建档素材（简历解析、对话、user_case）作为阶段 1 输入优先供给事实；生成结果页固定一行"请核对数字与经历表述"提醒。与项目叙事"AI 只组织不编造"红线的宽严不一是有意的：叙事要经得起面试官逐条追问，技能条是用户自己修改后才投出去的简历，责任主体是用户本人。

## 五、数据模型与状态机

（字段级 DDL 以 T10 落 schema.sql 时为准，这里定归属与最小结构，对齐附录 A 8.1。）

- **user_skill（技能条，归 profile）**：归属档案（profile_id）、生成批次（generation，重生成开新批次保留历史）、标题、段落文本、状态（draft / confirmed）、anchor_empty 标记、排序值。
- **user_skill_kp（锚定关联，归 profile）**：skill_id + kp_id，UNIQUE 约束兜底，反向索引支撑"考点 → 是否被锚定"查表。
- **画像状态机**：草稿 → 确认 → 定稿，落 user_profile（skill_status 实列）；存在未确认条目时不得定稿；**未定稿不参与生成关卡**（核心模块定义 2.1 口径不变）。
- **失效与重生成**：库侧知识点 retired / 合并后，消费时对锚定集做 active 校验，失效锚定标出并提示重生成；重生成只重写 user_skill / user_skill_kp（新批次），user_path / user_kp_state 语义对齐核心模块定义 2.2"可重开"。

## 六、与消费方的衔接

### 6.1 生成关卡（T11）

"是否简历授权" = 该知识点出现在当前档案**定稿**技能条（最新 generation、状态 confirmed）的锚定并集中，查 user_skill_kp 得出；承载模拟考聚合权重 ×1.5 与存活率定义域（核心模块定义 2.2 口径）。

### 6.2 简历主张存活率与升降级建议

- 存活率定义域 = 定稿技能条锚定的知识点集（0 锚定条不在内）；
- 模拟考的简历降级建议、复盘的升降级建议，对象都是**技能条**（原"主张项"）：某条技能条锚定的考点被反复打穿 → 建议降级该条措辞或删除；练深了 → 建议升级措辞。建议写回触发它的档案（profile api）。

## 七、LLM 入口与成本

- 新增 LLM 入口 `skill_draft`（技能条起草）：Tier.QUALITY、LimitKey.NONE（C 端消费类，受单用户合计硬熔断兜底，名下全部档案共享配额；全站总熔断已按决策清单 D32 取消），随 T10 在 LlmPurpose 枚举登记并自动进常量组下发（CLAUDE.md 约定）；
- 两阶段是同一入口的两个 prompt 模板；调用计数按 purpose × 天落 llm_usage_daily；
- 限额与熔断命中按核心模块定义 4.2 降级（生成失败可重试，不阻塞建档其他步骤）。

## 八、域字典的去留（B9 收口）

- 职责收敛为**知识点分域归属**一处：簇挂域（kp_cluster.domain_id）、B 端知识点筛选与关卡组按域组织；
- 域数据由种子维护（T4 已落 skill_domain 表与种子），B 端**不做域管理页**；知识点管理页的域下拉与筛选消费 kb meta 只读接口（T4 已落）；
- skill 包解散，skill_domain 归 kb 包（决策清单 D30 / B9 收口）；
- 域判据（按稳定技术领域切、具体技术不立域）见核心模块定义 3.1（D29）；种子域 Elasticsearch 的混层处理待决 B10。

## 九、任务口径

- **T3 缩编为设计任务**（已完成 2026-09-24）：原"域字典 CRUD + SkillsView 接线"取消，本 PRD 即其产出；
- **生成实现并入 T10 建档**：两阶段生成、锚定校验、编辑确认、状态机、失效检测随 T10 交付；前端 ProfileView 含技能条生成 / 编辑 / 确认交互；
- 依赖顺序不变：T10 前置 T4（库菜单数据源）与 T2（模型接入）。

## 十、范围外

- 简历整篇排版与导出（PDF / Word）：技能条只覆盖"个人能力"部分，简历整体成稿另立需求；
- 投递版自动分档（超两页自动拆条）：靠用户手动编辑，不做规则引擎；
- 生成结果的多版本对比与 A/B：单批次保留（generation），不做版本 diff；
- 技能条历史批次的管理界面：数据保留，界面不做。

## 十一、验收清单（随 T10 验收）

1. 建档对话 → 生成 → 编辑 → 逐条确认 → 定稿全流程可跑；
2. 幻觉考点 ID 被结构校验拒绝（构造菜单外 ID 的生成结果验证）；
3. 跨条重复锚定合法保留；0 锚定条正常入库并打标记、不进存活率定义域；
4. 未定稿时生成关卡被拒；定稿后授权查表正确（命中 / 未命中各验一）；
5. 库侧知识点 retired 后，消费侧能检出失效锚定并提示重生成；
6. 生成结果页有"请核对数字"提醒；skill_draft 用量进 llm_usage_daily 与系统配置页用量对照。
