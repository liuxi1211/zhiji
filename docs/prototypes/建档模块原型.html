建档Profile · /profile · 对应核心模块定义 2.1

建档是用户进入产品的第一站：最多 3 份简历档案，档案是备考上下文的顶层归属。 有简历就上传解析，没有简历就跟 AI 聊；LLM 从简历和对话里两阶段生成技能条（按域起草 → 逐条锚定考点），用户逐条拍板。 产出四样东西：技能条集、目标职级、备考计划、项目素材。建档不答题、不摸底，入口永远没有考试。

  • 墨青 · 主色 / 定稿确认
  • 铜 · 只承担「刻度 / 待拍板」语义
  • 难度五色（1–5，闯关原型使用）

模块 01 · PROFILE

建档

流程带即状态机：来源 → 对话/解析 → 技能条逐条拍板 → 职级与计划 → 定稿。画像走「草稿 → 确认 → 定稿」状态机，存在未确认条目时不得定稿。

1来源上传简历 / AI 对话
2解析 · 对话简历抽文本 · 项目素材沉淀
3技能条拍板两阶段生成 · 逐条确认
4职级 · 计划目标职级五档 · 备考计划
5定稿画像进学习地图

口径对照 · 设计元素 ↔ 核心模块定义 2.1 / 技能库PRD

原型中每一个非常规元素都有产品条款出处，评审时逐条核对；实现时以现行文档为准。

设计元素口径出处
「已建 2 / 3」新建档案位账号 1 : 档案 ≤3（user_profile，附录 A）
档案卡状态徽标「草稿 / 已定稿」+ 三站轨道画像状态机 draft → confirmed → finalized（user_profile.skill_status）；存在未确认条目不得定稿，未定稿不参与生成关卡
「跟 AI 聊」入口与上传并列无简历用户同样建档，档案形态为不含简历原件的默认档案，其余流程完全相同
对话中浮出「项目素材卡」（数字 / 冲突 / 结果）对话里聊到的项目细节沉淀为 user_case，后续是项目叙事与模拟考追问的原料
技能条左侧虚线→实线；「确认 / 改措辞 / 删掉 / 补一条」LLM 两阶段生成 + 用户逐条拍板：不熟的删掉、漏掉的加上、措辞不准的改掉（技能库PRD）
锚定考点 chips「锚定集就是授权数据源」user_skill_kp 锚定关联（D30）；授权推导、存活率定义域；幻觉考点被结构校验拒绝
「软素质条 · 不计入简历主张存活率」0 锚定条标记不进存活率定义域（核心模块定义 3.1）
「事实数字只修措辞、不过分改写」技能条事实数字按不过分干预口径处理（技能库PRD 4.3）
职级五档 + 「按年限推测，可改」提示level_target CHECK 五档；没说就按年限推测缺省值，用户随时可改（年限→职级映射表为待办，实现前定稿）
「建档不答题、不摸底——这里永远没有考试」建档不答题、不摸底，入口永远没有考试（2.1 边界）
解析预览「AI 整理 · 待你确认」+ 可直接改简历上传解析先行人工预览；解析文本只是技能条草稿原料
定稿页 CTA「生成学习地图 →」建档与生成关卡的模块衔接点；档案切换即上下文切换、进度互不污染
