## 一、二期开发（方向已定，排期推迟）

### 1.1 复核到期扫描与复核到期队列（原 T9 拆出）

- **功能**：scheduler 模块定时扫描内容复核到期（知识库PRD 8.3），把过期内容推入 B 端校对流转页的「复核到期」队列；处理动作：进知识点编辑页更新内容（复核到期重置）、确认仍有效（到期顺延）、确实废弃的走下线。调度状态持久化在库里，重启不丢。
- **价值**：技术结论会过期（ES / JVM 版本演进后老答案不再成立），只有"最后更新时间"无法触发复核；这是"内容可信"产品目标（知识库PRD 第二节）的长期保障机制。
- **暂缓原因**：内测期内容量级小（50 个知识点）且更新频繁，一期靠知识点管理页的「复核是否到期」筛选人工巡检即可覆盖；scheduler 定时任务没有提前引入的必要。
- **一期现状**：复核到期时间照常随校对通过 / 编辑保存写入（kp_main / kp_cluster 的 review_due_at 实列与索引 T4 已落库，schema 注释口径不变）；一期不建 scheduler 包、无定时任务。
- **启用条件**：二期开发排期；或知识点量级超出人工巡检可覆盖（如 >200 条）时提前。

### 1.2 申诉复核队列骨架（原 T9 拆出）

- **功能**：B 端校对流转页第三队列，承接 C 端判定申诉（决策清单 D6）：查看判定引用的用户原话与要点快照，人工确认后改判"不计入档位"（appeal_status → excluded）或维持原判。
- **价值**：判定可信度的纠错闭环，模拟考"标记申诉"（决策清单 D6、核心模块定义 2.5）在 B 端的承接面——"改判权留在人手里"需要人工处理的地方。
- **暂缓原因**：申诉来源（C 端模拟考申诉入口）在 T15 才出现，一期做队列骨架无单可接、纯空转；内测期申诉量级极小。
- **一期现状**：申诉标记照常落库（answer_log.appeal_status，随 T15 实现）；队列就位前如出现申诉，人工查 answer_log 处理——只改 appeal_status，判定档位与要点快照不动（改判口径与队列版一致）。
- **启用条件**：二期，与复核到期队列一并在校对流转页补齐（页面骨架按三队列预留）。

### 1.3 批量上线（原 T9 拆出）

- **功能**：校对流转页勾选多条 reviewed 内容一次上线（B端管理台PRD 第八节），校对完成与上线时点解耦。
- **价值**：批量省的是重复点击，多人协作下可"批量校对后择时统一上线"。
- **暂缓原因**：单条「通过并上线」已可用，50 个知识点量级逐条点击成本可接受；批量动作不省任何一道人工关（不校不上线红线不变），是纯效率优化、优先级低。
- **一期现状**：上线走单条「通过并上线」（校对流转页与知识点编辑页均可达）。
- **启用条件**：二期；或单批校对条数大到逐条点击成为实际负担时提前。

### 1.4 素材定时批处理（T6R 拆出，2026-10-08）

- **功能**：定时扫描 approved 态素材自动触发 LLM 预处理重写（改造计划 C1），省去人工点「批量预处理」。
- **价值**：素材量大时省重复点击，与复核到期扫描同属 scheduler 二期范围。
- **暂缓原因**：一期手动单条 + 批量勾选（前端逐条串行编排）已覆盖；重写为分钟级 LLM 调用，自动批处理宜与人工复核节奏协同设计，提前引入徒增失控面。
- **一期现状**：预处理仅人工触发（单条「预处理」/ 勾选「批量预处理」≤100）。
- **启用条件**：二期与 scheduler 一并评估；或素材吞吐量明显超出人工触发节奏时提前。

### 1.5 素材批量入池（T6R 拆出，2026-10-08）

- **功能**：preprocessed 态素材勾选多条一次「复核通过并入池」（改造计划 C11 拆出项）。
- **价值**：改写质量稳定后省逐条复核点击。
- **暂缓原因**：复核是第二道人工门（挡"整理过程引入的错误"），批量入池会整体绕过四项要点清单确认——一期无批量入口防绕过；待复核确认留痕机制完备（如逐条清单落库）后二期评估。
- **一期现状**：复核为逐条动作，通过时间落 pooled_at 留痕。
- **启用条件**：二期；或复核留痕机制完备且素材吞吐成为实际瓶颈时提前。

### 1.6 批次级孤儿图片清理（T6R 拆出，2026-10-08）——**已销账（2026-10-09）**

- ~~功能：定期扫描无引用命中的批次导入图与补图资产，清理数据库行与磁盘文件~~ **不再需要**：批次概念与 kp_source_asset 表均废止（决策清单 T6R 2026-10-09 增补），图片改为「落盘即真相」路径约定——导入命中按引用路径落盘、未被引用的图片直接不落盘、删除文档连带删除整个图片目录（编辑中间态孤儿随删除统一回收）——系统中不存在孤儿资产。

### 1.7 素材待办纳入统一待办中心（T6R 拆出，2026-10-08）

- **功能**：把素材库的待审核 / 待复核积压聚合进校对流转页的统一待办中心（改造计划 C13）。
- **价值**：待办一处清账，避免维护者遗漏素材侧积压。
- **暂缓原因**：素材库页的状态筛选已可承担定位（待审核 / 待复核各一筛即得）；统一待办中心一期只上成稿校对队列（D34），不宜随 T6R 扩容。
- **一期现状**：素材待办留在素材库页，由状态列与筛选承担。
- **启用条件**：二期与校对流转页三队列点亮一并评估。

### 1.8 阶段二：资料归一成文与 C 端学习区（D36 拆出，2026-10-09）

- **功能**：[资料讲解体系改造计划](资料讲解体系改造计划.md) 的第二阶段——①按簇把挂载资料（kp_doc_rel 反查 + 簇内 kp_doc）经 AI 多源汇总编辑产出标准化长文（origin=normalized，冲突清单复用 T8 机制，人工校对走同一状态机），逐步替换 source 挂载；②C 端学习区（域 → 簇 → 资料列表 → 阅读页，「相关题目」反向跳练）。
- **价值**：标准化文档是对标自建 JavaGuide 的重点建设方向；归一稿是持久合规形态（多源汇总+人工校+出处全留）；学习区让资料库成为练的入口补充与引流资产。
- **暂缓原因**：阶段一（kp_doc 落表 + 血缘挂载 + B 端管理）先行——挂载关系图是阶段二归一的输入语料图，先攒血缘与挂载数据，归一才有料可汇；C 端整体未开发。
- **一期现状**：阶段一随资料讲解体系改造任务落地；source 型资料 B 端可见可管，C 端不展示。
- **启用条件**：阶段一挂载量起来（各簇平均 ≥2 篇挂载资料）或 C 端学习区进开发排期，二者先到为准。

### 1.9 簇分组导航层（单域簇数膨胀后的中间分组）

- **功能**：kp_cluster 与 skill_domain 之间加一层轻分组（sketch：kp_cluster_group 表 + kp_cluster.group_id 可空列，纯导航不承载内容职责；拒绝 parent_id 自引用——分组节点与内容簇混表语义两可）。
- **价值**：D29 把域锁死 6~10 个、具体技术全部落簇，内容增长全部灌进簇层；单域 40+ 簇后 B 端簇列表与 C 端学习地图（关卡组内关卡数）会拥挤。
- **暂缓原因**：当前全库十来个簇，远未触达；无迁移顾虑（加表加列纯增量、kp_main 挂载点不动），推迟零成本；现在按想象划组是空壳结构（T6R「无含义结构不引入」同款逻辑）。
- **启用条件**：单域活跃簇数 ≥ 15，或 C 端学习地图（T11）PRD 开工时，先到为准。

## 一A、范围外但需记录的后置事项

- **图片进入知识内容与对外输出策略（T6R，改造计划 C9；2026-10-09 与 D36 合并口径）**：本期素材图片只做到素材域链路（采集 / 存储 / 渲染 / 重写保护 / 候选传递）；用户已拍板方向——图片后续做**人工审核**（有问题的引用手动编辑删除，不配图是合法终态），入池即焚后图片引用随 std_text 资产化（kp_doc 快照内按素材路径约定渲染）；成稿组料前剥离图片引用与 `asset:` 标记口径不变；对外输出（版权口径——保守改写使成品更贴近原文，原"独立成文、不搬运独创性表达"的防线强度后移；禁转仓库挂载资料清理检查点挂公网开放前）随公网合规清单一并处理。触发条件：用户启动专门评审时立项，与公网开放检查点合并。

## 二、实现前定稿事项（随对应任务收口，自核心模块定义第七节迁入）

> 这几条不是"不做"，是"做之前必须先定"，登记在此防遗漏；定稿后回改对应设计文档并销账。

- **职级基线与停止点标定**：这是漏题风险的真实所在（不在难度映射——那已结构性排除）。标定键统一为「知识点 × 职级档位」（初级/中级/高级/资深/专家），年限只是建档时推测缺省职级的参考，不是标定维度；需标定两样：哪些知识点对哪个职级档位必问（决定基础关卡组组成，面中级岗就有中级的基础关组）、每题每档停在第几层（决定过关尺子）。标定粒度详设时定；人工校对清单加入完整性检查项。承载已拍板：kp_main 的 level_req JSON（每档 required + stop_layer）加 baseline_levels 查询实列（SQLite 陷阱 E 的实列化先例），不新增表；剩余待办是标定内容本身。

- **年限→职级缺省映射表**：建档"没说职级就按工作年限推测"需要一个缺省映射（如 0-2 年→初级、3-5 年→中级、6-8 年→高级…），推测错了用户可改，但缺省值要合理。建档实现（T10）前定稿。

- **学习地图信息密度专项设计（决策清单 D3 已拍板记录）**：地图承载多关卡组 × 关卡 × 前置锁 × 放弃分区，信息密度可能违背企划书"几百个知识点永不一次性铺开"的原则。约束已定：默认按关卡组折叠、首屏只暴露"下一步闯哪"的系统建议、关卡内容点击才展开；具体的前端布局与交互样式留专项设计（前端实现 T11 前完成）。

## 三、条件触发（满足条件再立项，自核心模块定义第七节迁入）

- **成就系统**：每个技能域一个成就（如 Redis 域、Elasticsearch 域），用户完成该域关卡组的全部题目即获得；成就形态为头像或标签，展示在个人资料上，所有人可见。多域成就叠加可表达"多个领域精通 = 大神"这类身份信号。触发条件：公开展示意味着个人数据要脱离"单机自用"的边界，等公网多用户运行稳定后再做，届时按"账号公开资料页"立项。实现约束（先行记录）：成就判定应基于关卡组的完成状态推导，不新增独立打卡表。

- **公网部署合规清单（决策清单 D16；D17 调整为公网开放时再办、不阻塞开发）**：域名 ICP 备案（大陆服务器对外提供网站服务的前置）、全站 HTTPS（登录口令与简历数据的传输保护）、注册页隐私与用户协议说明（简历属个人信息，收集须告知）、知识库页面内容来源声明、`data/` 目录（SQLite 文件与上传素材）定期备份。触发条件：公网开放前办齐，不阻塞开发。
