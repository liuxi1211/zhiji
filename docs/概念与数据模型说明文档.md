## 一、系统目标

构建一个可长期维护、可扩展、可精准推送的面试学习系统，支持：

1. 按科目 / 分类浏览考点
2. 考点 → 详解 → 资料的消费路径
3. 追问链无限下钻
4. 按简历关键词精准推送考点
5. 多维筛选：标签、难度、来源
6. 资料与考点多对多，支持互相推导

## 三、科目（Subject）

### 3.1 定义

科目是系统最稳定的顶层技术领域，不随具体技术增减而变化。

### 3.2 判断标准

一个东西要成为科目，必须满足：

1. 是**技术领域**，不是具体技术产品
2. 数量少（6~10 个）
3. 极稳定，不随技术增减
4. 下面可以挂多个分类

### 3.3 推荐科目

```text
Java
Python
数据库
中间件
计算机基础
系统设计
```

### 3.4 常见错误

| 错误分法 | 问题 |
|---|---|
| 科目：Java、Python | MySQL、Redis、操作系统放哪？ |
| 科目：Java、Python、数据库 | 维度和层级混了，Java 是语言，数据库是领域 |
| 科目：Java、Python、MySQL、Redis | 科目会爆炸，MySQL、Redis 是中间件，应该平级 |

### 3.5 结论

- 科目按**技术领域**分，不按语言分
- MySQL、Redis、RocketMQ、ES、K8s 都不是科目
- 它们都是**分类**

## 四、分类（Category）

### 4.1 定义

分类是科目下的树形归类节点，用于精准归类和推送。

### 4.2 判断标准

一个东西要成为分类，必须满足：

1. 是**具体技术、领域、主题**
2. 可以挂在科目下
3. 可以有子分类
4. 考点挂在分类下

### 4.3 推荐分类粒度：三级

```text
科目 → 领域 → 主题 → 考点
```

示例：

```text
Java
  └── 并发
        └── 锁
              └── 考点：synchronized 原理
```

### 4.4 分类树示例

```text
Java
  ├── 基础语法
  ├── 集合
  │     ├── HashMap
  │     └── ConcurrentHashMap
  ├── 并发
  │     ├── 锁
  │     ├── 线程池
  │     ├── CAS
  │     └── AQS
  ├── JVM
  │     ├── 内存结构
  │     ├── GC
  │     └── 类加载
  └── Spring
        ├── IOC
        ├── AOP
        └── SpringBoot

Python
  ├── 基础语法
  ├── 数据结构
  ├── 并发
  └── 常用库

数据库
  ├── MySQL
  │     ├── 事务
  │     │     ├── ACID
  │     │     ├── 隔离级别
  │     │     └── MVCC
  │     ├── 索引
  │     └── 锁
  ├── PostgreSQL
  ├── Redis
  │     ├── 数据结构
  │     ├── 持久化
  │     └── 集群
  └── MongoDB

中间件
  ├── RocketMQ
  ├── Kafka
  ├── ES
  └── K8s

计算机基础
  ├── 操作系统
  ├── 计算机网络
  └── 算法与数据结构

系统设计
  ├── 高并发
  ├── 分布式
  └── 微服务
```

### 4.5 分类与科目的边界

| 维度 | 科目 Subject | 分类 Category |
|---|---|---|
| 数量 | 少（6~10 个） | 多 |
| 稳定性 | 极稳定 | 可增减 |
| 例子 | Java、数据库、中间件 | MySQL、Redis、事务 |
| 是否可树形 | 否 | 是 |
| 作用 | 顶层导航 | 精准归类 |

一句话：

> **科目是稳定的领域，分类是可变的节点。**

### 4.6 分类与标签的关系

- 分类是**主归属**，一个考点只属于一个分类
- 标签是**辅助关联**，一个考点可以有多个标签

示例：

```text
考点：MySQL 事务有哪些
  分类：数据库 → MySQL → 事务
  标签：Java、高频、面试常问
```

这样：

- 从“数据库”科目能找到它
- 从“Java”标签也能筛到它
- 简历写“Java”时，可以通过标签推给它

## 五、考点（Exam Point）

### 5.1 定义

考点是用户看到的、可被问出来的问题。

### 5.2 示例

```text
MySQL 事务有哪些
Redis 为什么快
RocketMQ 集群架构
synchronized 原理
JVM 内存结构
```

### 5.3 归属

- 考点挂在**分类**下
- 一个考点只属于一个主分类
- 通过标签可以多维度关联

### 5.4 用户界面

```text
考点：MySQL 事务有哪些
  [详解]
  追问：
    - MVCC 原理
    - 隔离级别怎么实现
    - Read View 是什么
```

## 六、详解（按钮名）

### 6.1 定义

“详解”是**用户视角的按钮名**，不是数据实体。

### 6.2 作用

用户看不懂考点时，点击“详解”，展示关联的资料。

### 6.3 与资料的关系

- 用户点“详解” → 查 `exam_point_material` → 拿到多个 `material`
- “详解”是界面按钮，`material` 是数据实体

---

## 七、资料（Material）

### 7.1 定义

资料是后端维护的内容实体，包括文章、视频、代码、链接等。

### 7.2 判断标准

一个东西要成为资料，必须满足：

1. 是**内容实体**，不是问题
2. 可以被多个考点关联
3. 有类型、来源、标题、内容

### 7.3 资料类型（Material Type）

| 类型 | 说明 |
|---|---|
| 概念解释 | 这是什么 |
| 原理讲解 | 为什么这样 |
| 面试回答 | 怎么答 |
| 代码示例 | 怎么写 |
| 对比分析 | 有什么区别 |
| 视频 | 视频链接 |
| 链接 | 外部文章 |

### 7.4 考点与资料的关系

**多对多**：

- 一个考点可以关联多个资料
- 一个资料可以关联多个考点

### 7.5 生产流程

| 方向 | 流程 |
|---|---|
| 资料 → 考点 | 先有资料，抽取出考点，建立关联 |
| 考点 → 资料 | 先有考点，补充资料，建立关联 |

两种方向走同一张关联表 `exam_point_material`。

---

## 八、追问（Follow-up）

### 8.1 定义

追问是对考点的深入延伸，**本身也是考点**。

### 8.2 判断标准

一个追问要成立，必须满足：

1. 是一个**可被问出来的问题**
2. 离开父考点也能独立存在（可选）
3. 可以有自己的资料、标签、难度

### 8.3 追问是独立考点

- 追问存在 `exam_point` 表中
- 追问通过 `exam_point_relation` 挂在父考点下
- 追问可以有多个父考点
- 追问可以独立被搜索、推送

### 8.4 是否可独立存在

用 `exam_point.is_standalone` 标记：

| 值 | 含义 |
|---|---|
| true | 可独立检索、推送 |
| false | 只能从父考点进入 |

### 8.5 关系类型

`exam_point_relation.relation_type`：

| 值 | 含义 |
|---|---|
| follow_up | 追问 |
| related | 相关 |
| prerequisite | 前置知识 |

### 8.6 示例

```text
考点：MySQL 事务有哪些
  ├── 资料：事务 ACID 讲解
  ├── 资料：隔离级别原理
  └── 追问：MVCC 原理
        ├── 资料：MVCC 详解
        └── 追问：Read View 是什么
```

追问本身也是考点，可以独立被搜索、推送。

---

## 九、标签（Tag）

### 9.1 定义

标签是给考点贴的自由标记，用于多维筛选。

### 9.2 判断标准

一个东西要成为标签，必须满足：

1. 是**标记**，不是归类
2. 可以跨分类、跨科目
3. 多对多

### 9.3 示例

```text
考点：MySQL 事务有哪些
  标签：Java、高频、面试常问、数据库
```

### 9.4 标签与分类的区别

| 维度 | 分类 Category | 标签 Tag |
|---|---|---|
| 性质 | 归类 | 标记 |
| 结构 | 树形 | 扁平 |
| 关系 | 一对多 | 多对多 |
| 作用 | 导航、推送 | 筛选、搜索 |
| 是否必须 | 必须 | 可选 |

一句话：

> **分类是长出来的，标签是贴上去的。**

## 十、难度（Difficulty）

### 10.1 定义

难度是给考点标的标准化分级，用于学习路径。

### 10.2 分级

```text
简单
中等
困难
```

或更细：

```text
入门
基础
进阶
高级
专家
```

### 10.3 示例

| 考点 | 难度 |
|---|---|
| Redis 有哪些类型 | 简单 |
| Redis 为什么快 | 中等 |
| Redis 持久化 RDB 和 AOF 区别 | 中等 |
| Redis 集群脑裂怎么处理 | 困难 |
| MySQL 事务有哪些 | 简单 |
| MySQL MVCC 原理 | 困难 |

### 10.4 难度与标签的区别

| 维度 | 难度 | 标签 |
|---|---|---|
| 数量 | 固定几档 | 自由多 |
| 是否标准 | 标准化 | 自由 |
| 作用 | 学习路径 | 多维筛选 |

一句话：

> **难度是纵向深浅，标签是横向分类。**

## 十二、数据模型

### 12.1 整体关系

```text
subject
  └── category (树形)
        └── exam_point
              ├── exam_point_material
              │     └── material
              │           └── material_type
              ├── exam_point_relation (parent_id, child_id)
              ├── exam_point_tag
              │     └── tag
              ├── difficulty
              └── source
```

### 12.2 表结构说明

#### subject（科目）

```text
id
name
```

#### category（分类）

```text
id
subject_id
parent_id        # 自关联，支持树形
name
level            # 层级：1 领域 / 2 主题 / 3 子主题
path             # 可选，路径如 /java/concurrency/lock
```

#### exam_point（考点）

```text
id
subject_id
category_id
title
is_standalone    # 是否可独立存在、独立检索
difficulty_id
source_id
```

#### exam_point_relation（考点关系）

```text
id
parent_id        # 父考点
child_id         # 子考点（追问 / 关联 / 前置）
relation_type    # follow_up / related / prerequisite
```

#### material（资料）

```text
id
title
content
material_type_id
source_id
```

#### material_type（资料类型）

```text
id
name             # 概念解释 / 原理讲解 / 面试回答 / 代码示例 / 对比分析 / 视频 / 链接
```

#### exam_point_material（考点资料关联）

```text
id
exam_point_id
material_id
```

#### tag（标签）

```text
id
name
```

#### exam_point_tag（考点标签关联）

```text
id
exam_point_id
tag_id
```

#### difficulty（难度）

```text
id
name             # 简单 / 中等 / 困难
```

#### source（来源）

```text
id
name             # 书名 / 视频 / 面经 / 官方文档
```

## 十三、用户界面模型

```text

    - MVCC 原理
    - 隔离级别怎么实现
```


### 13.3 追问页

点击追问后进入新的考点页：

```text
考点：MVCC 原理

  追问：
    - Read View 是什么
    - undo log 版本链
```

追问本身也是考点，可以独立被搜索、推送。

## 十四、简历推送模型

### 14.1 推送流程

```text
简历文本
    ↓
关键词提取
    ↓
匹配分类节点
    ↓
推送该分类下的考点
```

### 14.2 示例

简历写：

```text
熟悉 Java 并发，了解 JVM，用过 Redis
```

匹配：

```text
Java → 并发
Java → JVM
中间件 → Redis
```

推送这些分类下的考点。

### 14.3 精度控制

推送精度取决于分类粒度：

| 分类粒度 | 推送精度 | 维护成本 |
|---|---|---|
| 两级分类 | 较粗 | 低 |
| 三级分类 | 精准（推荐） | 中 |
| 四级分类 | 极准 | 高 |
